## 何を検査したか

- ナビゲーションの名前、通常のリンク、現在のページ。
- Enterで開く、Tabでリンクへ入る、Escapeで閉じてトリガーへ戻る。
- 兄弟グループの切替、外へフォーカスしたときの閉鎖、リンクの移動。
- リンクの追加・改名・削除と復元、入力値とカウンターの保持。
- strict TypeScript、axe WCAG A/AA、320pxの閉じた状態と開いたパネル。

同一不具合の修正では、全件が合格済みのコードに、ナビゲーション名の誤り、Guidesのリンク先の誤り、外側の最小幅640pxを追加しました。8件とも3項目の検査で失敗したことを確認し、診断付きで1回だけ修正させました。注入元・改変後のハッシュは各seed.json、注入処理はseed-plan.tsに残しています。

## 改善と解釈

Urushiの高速なグループ切替で、遅れて届くtoggleイベントに古い操作が勝つ問題を修正しました。型生成で数値リテラルのunionを保持し、columnsは1か2だけを受け付けます。context --compactは契約と共通規約を保持し、関係の薄いトークンを省きます。Rootに内部リスト用の表示クラスを付けないことも説明に追加しました。最終のUrushiは初回生成・仕様変更・同一不具合の修正の6画面とも独自診断0件でした。

成功率の全面的な優位性は示していません。直前のmeasured-v2では全ライブラリが生成・仕様変更とも全件合格しました。今回のshadcnの生成・仕様変更の失敗は最終的に修正されています。ただし別の同一不具合の修正課題では、幅320pxに対して333pxと321pxの横はみ出しが残り、2件とも不合格でした。2試行だけでモデル全般やライブラリ全体を順位付けできません。サイズの差と成功率は分けて判断します。

## 条件と記録

Base UI 1.9.0、radix-ui 1.8.1、shadcn new-york-v4のRadix版、React 19.3.1。依頼文、API資料、返答、使用トークン、生成コード、診断、画面、ライブラリソースを各runへ保存しました。AIはツールなし、履歴なし。費用はCLIが返さないため未計測です。入力トークンはAPI資料の長さにも左右されます。最終2実験の入力トークンはUrushi 65,417、Base UI 124,514、Radix 61,245、shadcn 88,500で、UrushiはRadixより少なくありません。

空で1pxにクリップされたaria-hiddenのフォーカス用spanだけはaxeの判定を別記録にしています。通常の要素の違反は除外しません。これはスクリーンリーダーの実利用で問題がないことを保証するものではありません。

baseline-v1とrepair-v1は検査校正用で成績から除外。前者にはsummaryの検索、各ライブラリの矢印開始条件、hoverとclickの競合がありました。後者は仕様変更済みコードに生成時点の検査を適用していたため使っていません。measured-v2とrepair-v2は改善前の結果として保存しています。
