トーストは、操作の結果を短く知らせる通知です。Toaster をページに 1 つ置き、クライアントのコードから `toast()` を呼びます。

## 使う場面

- 「保存しました」「削除しました（元に戻す）」など、操作の結果を知らせるときに使います。
- 通信の失敗など、操作のあとで分かった問題を知らせるときに使います。

## 使わない場面

- 先に進む前に答えが必要なことには Dialog を使います。
- 入力の誤りは、入力欄のそばに Field の `error` で示します。

## 必要な設定

- ルートのレイアウトに`<Toaster />`を1つ置きます。`label`は既定で「通知」です。`position`には`bottom-end`・`bottom-center`・`top-end`を指定できます。
- `toast(message, { description, tone, duration, action })`を呼び出します。`tone`は`neutral`・`ok`・`danger`から選びます。`action` は「元に戻す」のような 1 つの操作です。

## 振る舞い

- 丁寧な（polite）ライブ領域なので、読み上げを妨げずに伝わります。
- 5 秒で消えます（`duration: 0` で消えません）。ポインタを重ねるか、フォーカスがあるあいだは止まります。
- 消えるトーストは、置かれた端の方向へ横に抜けます。Chromium では高さも畳まれ、残りが滑って詰まります。動きを減らす設定では、フェードだけになります。
- モーダルのダイアログが開いているときは、そのダイアログの中の領域に出ます。外に出すと、見えていても操作も読み上げもできなくなるためです。閉じると、残っているトーストはページの領域に戻ります。

## 実装時の注意

- エラーを自動で消さないでください。失敗を知らせるトーストは `duration: 0` にします。
- 1つの操作で何個も表示しないでください。

## 処理中から結果まで

`toast.promise(promise, { loading, success, error })`で、ひとつの通知を処理中から結果へ更新できます。`success`と`error`には文字列、または結果を受け取って文字列や通知オプションを返す関数を渡します。失敗の通知は自動で消えません。`action`に再試行や取り消しを設定できます。

返り値は通知IDです。`toast.update(id, options)`で同じ通知の文言、進捗、操作を変更できます。`progress`は0〜100、`progressLabel`は進捗の名前です。`loading: true`のあいだは自動で消えず、処理が終わったら`loading: false`にします。

通知を閉じても元の処理は中断しません。閉じた通知は、処理が完了しても再表示しません。取り消しや再試行の実処理は、アプリのコールバックで実装してください。
