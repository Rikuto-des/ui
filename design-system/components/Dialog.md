Dialogはネイティブの`<dialog>`でモーダルを表示し、作業を中断して確認や短い入力を求めます。

## 使う場面

- 削除など、取り消せない操作を確認するときに使います。
- 先に進む前に終わらせる必要がある短い入力に使います。

## 使わない場面

- 操作の横に補足を出すだけなら Popover を使います。
- 操作の結果を知らせるだけなら、トースト（Toaster と toast()）を使います。

## 必要な設定

- `id`：`Dialog.Trigger` と `Dialog.Close` がこの id を参照します。
- `title`：必須です。見出しになり、ダイアログの名前として読み上げられます。確認ダイアログでは問いの形にします。
- `description`：任意です。何が起きるかを具体的に書きます。
- childrenには本文やフォームを置き、最後に`Dialog.Actions`を配置します。主な操作は右端に置きます。

## 振る舞い

- 開くと背景は操作できなくなり、ページのスクロールも止まります。フォーカスは中に閉じ込められ、閉じると開いたボタンに戻ります。
- `dismissible="any"`（既定）：Esc キーと外側のクリックで閉じます。`"closerequest"`ではEscキーだけで閉じます。`"none"`：明示的なボタンでしか閉じません（入力途中のフォームに使います）。
- `<form method="dialog">` の中で送信すると、ダイアログが閉じます。
- ここまですべて JavaScript なしで動きます。

## 実装時の注意

- ダイアログの中でさらにダイアログを開かないでください。
- 危険な操作の確認では、危険な側のボタンに`autoFocus`を付けないでください。キャンセルに付けます。

## 操作例と追加設定

操作例では編集・確認・反映を順に進めます。確認から戻っても入力は残り、次の手順の見出しや入力欄へフォーカスが移ります。
