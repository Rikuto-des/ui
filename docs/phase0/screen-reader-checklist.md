# スクリーンリーダーでの手動確認（Phase 0）

自動テスト（axe、アクセシビリティツリーの比較、キーボード操作）は 3 つのブラウザエンジンで通っています。ただし、実際の読み上げは人が聞いて確かめる必要があります。この表の順に確認し、結果を記入してください。

## 準備

1. `pnpm dev` でプレイグラウンドを起動し、http://localhost:5173 を開く。
2. JavaScript なしでの動作も見るときは、http://localhost:5173/static/index.html を開く（スクリプトが 0 個のページ）。
3. パックは上のバーで切り替える。読み上げはパックに関係しないので、Graphite だけで確認すれば足りる。

| 組み合わせ | 起動方法 |
|---|---|
| VoiceOver ＋ Safari（macOS） | ⌘F5 |
| VoiceOver ＋ Safari（iOS） | 設定 → アクセシビリティ → VoiceOver |
| NVDA ＋ Firefox（Windows） | Ctrl＋Alt＋N |
| NVDA ＋ Chrome（Windows） | 同上 |
| TalkBack ＋ Chrome（Android） | 音量キーの上下を 3 秒長押し |

## 結果の書き方

- 期待どおりなら ✓、違えば読み上げられた内容を書く。
- 問題があった項目は、ブラウザとスクリーンリーダーの版、再現手順を `docs/phase0/README.md` の「分かった制約」に追記する。

## 自動テストで確認済みのこと（参考）

- axe（WCAG 2.2 の A・AA）：2 パック × ライト／ダーク × 通常・ダイアログを開いた状態・ポップオーバーを開いた状態で、違反 0 件（Chromium、Firefox、WebKit）。
- アクセシビリティツリー：ダイアログが名前付きの dialog であること、見出し・説明・ボタンの構造。ポップオーバーが名前付きの dialog で、チェックボックスにラベルがあること。
- Chromium の実際のツリー：ダイアログが modal と報告され、背後のボタンがツリーから外れていること。ポップオーバーのトリガーが開閉状態（expanded）を持つこと。
- キーボード：Enter で開く、Esc で閉じる、フォーカスが中に閉じ込められる、閉じるとトリガーに戻る。
