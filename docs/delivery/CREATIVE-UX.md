# コンポーネントの機能・動き・UX改善

2026年10月29日。Combobox、Tabs、Toastに、選択や作業を進めるための機能と動きを追加しました。公開API、生成スタイル、説明、実際に操作できる詳細ページを更新しています。

## 実装

| コンポーネント | 追加した体験 | API |
| --- | --- | --- |
| Combobox | 候補のプロフィールを切り替えて比較し、確認してから確定。別名・専門分野でも検索できます。狭い画面では候補と詳細を縦に並べ、確定ボタンを残して内容をスクロールできます。 | `renderPreview`、`previewLabel`、`previewActionLabel`、候補の`icon`と`keywords` |
| Tabs | 選択位置とパネルの高さが260msで連続変化します。途中で切り替えても現在の位置から動き、入力した内容は保持します。動的なタブの追加・並べ替えにも追従します。 | `motion="smooth"`が既定。`motion="none"`で即時切り替え |
| Toast | 同じ通知の中で処理中・進捗・成功・失敗を表示。取り消しや再試行を実処理に接続できます。通知を閉じた後に処理が終わっても、通知は再表示しません。 | `toast.promise()`、`toast.update()`、`loading`、`progress`、`progressLabel` |

Comboboxの比較機能は任意です。`renderPreview`を指定しない場合は、従来どおり候補をクリックすると確定します。プレビューは読み取り用で、内部に操作ボタンを入れる設計にはしていません。

TabsとComboboxの動きは`prefers-reduced-motion`に従います。Toastは処理中、ポインタを重ねている間、キーボードフォーカスがある間は自動で消えません。更新で操作ボタンが消える場合は、閉じるボタンへフォーカスを移します。外部のアニメーションライブラリは追加していません。

実画面の確認で見つかったSafariでの確定時のフォーカス移動、長いプレビューのスクロール、API表の横スクロールも修正しました。Toastの見本は画面内の状態を更新するデモで、実ファイルの送信や削除は行いません。

## 検証

| 対象 | 結果 |
| --- | --- |
| コンポーネントの操作・関連回帰テスト | Chromium、Firefox、WebKitで72件成功。既存のChromium標準interest invoker向け分岐3件はスキップ |
| 詳細ページの新機能 | 4課題×3ブラウザ、12件成功 |
| 既存の一覧・起動・詳細・サイドバー | 45件成功 |
| Next.jsのSSR・JavaScript無効時・runtime | 36件成功 |
| 型検査、lint、生成、サイトビルド | 成功 |

成功した操作テストは重複を除いて計165件です。新機能の実ページ検証では320px、390px、1280pxの幅、ライト／ダークの開いたプレビュー、API表の矢印キー操作を確認しました。axeの対象ルールで違反はありませんでした。既存一覧の検証でも、全52コンポーネント、2パック、2テーマの表示・アクセシビリティ検査が通りました。

アプリ内ブラウザでは、デスクトップと319px幅でComboboxの比較・別名検索・確定、Tabsの入力保持、Toastの失敗から再試行・成功から取り消しを実際に操作しました。端末実機とスクリーンリーダーによる今回の追加機能の検証は未実施です。
