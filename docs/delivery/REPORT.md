# Urushiの実装・実測記録

2026年10月28日。実用アプリ、4コンポーネント、操作検証CLI、配布物を実装しました。競合比較ではUrushiとBase UIの成功率は同率です。今回の条件で配信サイズは最小でしたが、一般的な「圧倒的優位」を示す結果ではありません。

## 動く成果物

- Studio: http://localhost:3300
- コンポーネント一覧: http://localhost:3200/components/
- 比較結果: http://localhost:3200/docs/comparison/
- CLIの使用例: http://localhost:3200/docs/ai/
- 配布物: `dist/release/`の7パッケージ。SHA-256は`manifest.json`。

Studioは検索・状態の絞り込み・並び替え・ページ送り・複数選択・一括変更・新規作成・編集・設定を備えます。保存失敗時の入力保持と再試行、古い版での保存に対する409応答、ファイルへの保存を確認しました。初期データは架空です。認証・権限・共同編集用サーバーは含まないローカル実装例です。

Combobox、DataTable、DatePicker、Commandを公開APIとして追加し、contract、型、CSS、registry、ドキュメント、一覧プレビューと詳細ページを揃えました。全52コンポーネントです。

## 今回直した不具合と表示

- 入れ子のカレンダーを閉じると親の編集画面まで閉じる問題。
- カレンダーでキーを素早く押すと前の日付を選ぶフォーカス更新の競合。
- Safariでカレンダーを開いた直後や、ダイアログを閉じた後のフォーカス位置。
- 一括変更後に操作ボタンが消え、フォーカスの行き先がなくなる問題。
- Reactの`key`をDataTableの不明なpropとして扱う静的検査の誤判定。
- CLIからのaxe検査でBrowserContextが必要になる問題。実際の配布版CLIでも確認済み。
- 320px幅でコードとコピーボタンが重なる表示。言語名とコピーボタンを独立した行に配置。
- 日本語アプリ内の選択・ページ送り・空の検索結果、4コンポーネントの操作説明。

## 実際のAI比較

同じプロジェクト管理課題、API応答、型・操作・axe・390px幅の検査を使用しました。各ライブラリ2試行、生成と仕様変更に各最大1回の修正です。共通検査はChromiumで行い、Urushi独自のlintは合否から分けています。

| gpt-6-luna | 初回生成 | 生成の修正後 | 仕様変更 | 仕様変更の修正後 |
|---|---:|---:|---:|---:|
| Urushi | 2/2 | 2/2 | 2/2 | 2/2 |
| Base UI | 2/2 | 2/2 | 2/2 | 2/2 |
| Radix UI | 0/2 | 0/2 | 0/2 | 1/2 |
| shadcn/ui | 1/2 | 1/2 | 1/2 | 1/2 |

Radixの生成コードではフォーカス復帰、shadcnの一部では狭い画面での横はみ出しが残りました。各ライブラリ自体の実現可能性を示す評価ではありません。2試行・1課題から一般的な優劣は断定できません。

gpt-6.1-solも実行しましたが、32回の要求のうちコードを取得できたのは10回で、その後はHTTP 429となりました。取得できた初回生成5件はUrushi 1/1、Base UI 2/2、Radix UI 1/1、shadcn/ui 0/1です。生成3件と仕様変更の応答は欠測です。欠測を実装の失敗に数えたり、不均等な件数を2モデルの総合順位にまとめたりしていません。

2モデル合わせて54回の要求、32回の成功応答です。依頼・応答・使用トークン・コード・ソースのハッシュ・診断・画像を保存しました。最初の検査にあったラベル指定と開閉アニメーション待機の誤判定は修正し、コードを変えず別ディレクトリで再評価しています。初回記録は残しています。誤判定を含んだ修正依頼があるため、solの修正後成績は主比較から除外しました。

今回の追加課題はアプリの仕様変更です。依存バージョンの更新比較は既存の`generated/lifecycle-summary.json`の別実験です。

## 操作の失敗からAI修正後の再生まで

`urushi verify`はシナリオに沿ってブラウザを操作し、JSON、失敗した手順、アクセシビリティツリー、画像を保存します。成功は終了コード0、操作失敗は1です。シナリオはクリック・入力・キー操作・選択・再読み込み・表示や値やフォーカスの確認・axeに対応します。対象はrole/name、label、testId、withinで指定できます。

gpt-6-lunaが生成したRadixのコードと、そのモデルによる修正コードを同じCLIシナリオで再生しました。Escape後のフォーカス復帰は修正前に失敗、修正後に成功しました。AIの修正依頼には共通Playwright検査の診断を使い、CLIで保存済みコードを独立して再検証しています。CLIが自動でモデルを呼んだり、ソースを書き換えたりした結果ではありません。

再生: `node evals/product/replay.ts`。証拠は`evals/product/review/ai-replay/`です。

## 実機・読み上げで残る確認

Macの実画面では編集・検索候補・無効項目・カレンダーと親画面への復帰、詳細ページの表示、比較表を操作して確認しました。幅390pxのWebKitによる操作画像も保存しました。これはiPhone本体の検証ではありません。

VoiceOverをSystem Settingsから有効にするところまで進めましたが、操作ツールがVoiceOverへのアクセスを拒否し、読み上げを確認できませんでした。その後、VoiceOverがオフであることを確認しました。Windows＋NVDA環境は利用できていません。ユーザーはiPhoneを手動操作する方針ですが、操作結果はまだ受け取っていません。

iPhoneではMacと同じWi-Fiに接続し、Safariのアドレス欄に`http://192.168.11.4:3300`を入力します。案内したURLはMacからHTTP 200を確認済みです。検索、担当者の選択、カレンダーから編集画面への復帰、保存と再読み込みを実機で確認する必要があります。
