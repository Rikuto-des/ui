# Urushi 0.1.0-beta.1の配布準備

2026年10月30日に、β版の配布候補を用意しました。npmと本番サイトへの公開はまだ行っていません。

## 配布候補

- ソースは`ab60022b174f45cce3723bbed04d055543af554a`に固定しました。非公開リポジトリの`codex/beta-0.1.0`ブランチに保存しています。
- [CIの実行記録](https://github.com/Rikuto-des/ui/actions/runs/41032607879)は7ジョブすべて成功しました。同じコミットで生成・検証された7パッケージを取得しています。
- 配布ZIPは`dist/urushi-0.1.0-beta.1-ab60022.zip`です。7つのtgzに加え、導入方法、対応範囲、変更履歴、ライセンス、第三者のライセンス表示、SHA-256のmanifestを収録しています。
- [GitHub Release下書き](https://github.com/Rikuto-des/ui/releases/tag/untagged-0dba516a608da48fe648)に、7つのtgz、manifest、パッケージZIP、サイトZIPを添付しました。10ファイルのハッシュとサイズも照合済みです。

作業中のファイルとステージ状態は元のワークスペースに残しています。別の作業コピーで配布用コミットを作成しました。対象ソース1,258ファイルの一致は[ハッシュ記録](beta-0.1.0/source-hashes.json)で確認できます。過去の比較資料は以前の保存内容を維持し、Studioのローカル保存データは配布コミットに含めていません。

## 今回修正した問題

デモの画面が表示されてもJavaScriptの読み込みが終わっていない間に操作でき、最初の入力やキー操作が失われる問題を修正しました。各デモとアイコン検索は、操作の準備が整ってから有効になります。JavaScriptの取得を遅らせた状態でも、最初の操作が反映されることを検証しています。

Comboboxのプレビューは、登場アニメーション中も文字の濃さを保つようにしました。移動する動きは残しています。3ブラウザでコントラストとアニメーション開始・途中・終了時の表示を確認しました。

Studioでは、入力エラー後に遅れてフォーカスが戻り、担当者欄への入力を妨げる問題を修正しました。描画を止めた状態で問題が再現するテストを作り、修正後は3ブラウザで通ることを確認しました。

CLIの案内と内部依存を`0.1.0-beta.1`に揃え、内部パッケージのバージョンを固定しました。サイトの導入コマンドも、利用者のプロジェクトで実行する`npx urushi`に統一しました。

サイトの本番ビルド464ファイルを`dist/urushi-site-ab60022.zip`にまとめました。これはローカルの本番ビルドから作ったもので、CIから取得したパッケージとは別です。ビルド後の変更は検証コード3ファイルだけで、本番ソースに差分がないことも確認しました。静的ホスティングのルートに配置する構成で、サブディレクトリ公開には追加設定が必要です。実際の配置と公開URLでの確認はまだ行っていません。

## 公開前に残ること

1. npmの認証確認が401で失敗しています。利用者本人によるログインと、`@urushi`スコープの権限確認が必要です。パスワードやトークンをチャットに貼る必要はありません。
2. GitHubリポジトリは非公開です。履歴も含めて公開するか、公開用に範囲を分けるかを決める必要があります。非公開のまま配布する場合は、利用者がアクセスできる不具合報告先を用意します。
3. サイトはローカルで起動しています。本番の公開先とURLは未確定です。
4. npm公開後は、公開レジストリからの新規導入を確認します。tgzからの導入成功とnpm公開の成功は区別します。

iPhone・Android実機とVoiceOver・NVDA・TalkBackは未検証です。最低対応ブラウザのバージョンもまだ保証していません。Next.jsのビルドで出る新しいCSS疑似要素の警告は、[対応範囲](../release/COMPATIBILITY.md)に記載しています。

公開時の具体的な操作は[公開手順](beta-0.1.0/PUBLISHING.md)、配布内容の紹介は[Release原稿](beta-0.1.0/RELEASE-NOTES.md)を参照してください。
