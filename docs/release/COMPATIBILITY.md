実際に起動したブラウザーの値は `browser-evidence.json` に記録しています。GitHubのLinux環境の結果は `docs/delivery/` のCI記録を参照してください。最低対応バージョンや、古いSafari／Android WebViewへの対応はまだ保証していません。

Dialog、Popover、CSSの `light-dark()` など、現行ブラウザーの機能を使います。任意ランタイムには一部機能の補助がありますが、古いブラウザー全体を対応範囲に加えるものではありません。対象製品が古いブラウザーを必要とする場合は、その版を追加検証してから採用してください。

Next.jsのビルドでは、`::scroll-button`などの新しいCSS疑似要素にパーサー警告が出ます。今回の生成CSSに該当セレクターが残ることは確認済みです。Next.js実装例の36件はDialog、Popover、フォーム、Tabs、Menuなどの範囲で、全コンポーネントを各フレームワーク上で網羅した検証ではありません。

任意ランタイムの登録完了は、`html[data-urushi-runtime="ready"]`で確認できます。ArrowDownなどの追加キー操作を自動検証する場合に待機対象として使えます。これはアプリ独自のデータ取得やReactの検索処理の準備完了を示すものではありません。ランタイムなしの標準HTML操作は、別のシナリオで検証します。

## β版の利用範囲

試作や検証用のプロジェクトから試してください。β期間中はAPI、見た目、動作を変更する場合があります。バージョンを固定し、更新前に変更履歴を確認してください。実機と読み上げの未検証項目は、確認できるまで対応済みとは扱いません。

## バージョンの扱い

ソースのワークスペース版は現在 `0.0.0`、配布検証用tgzは `0.1.0-beta.1` です。公開された版を上書きする運用はしません。公開前の候補tgzはファイル名だけで同一性を判断せず、`dist/release/manifest.json` のSHA-256を記録します。

今後のリリースでは、パッチ版は互換性を保つ不具合修正を基本とします。0.xの互換性を壊すAPI・見た目・動作の変更はminor版にまとめ、変更点と移行手順を同時に出します。意図しないフォーカス・キーボード操作の退行は不具合として扱います。

公開後のAPI廃止は、原則として少なくとも1つのminor版で代替APIと非推奨表示を先に提供します。安全上の理由などで例外が必要な場合は、理由と影響を明記します。これらは今後の運用方針であり、まだ発行していない版の提供を約束するものではありません。

## 更新と移行

1. アプリの変更をGitに保存し、現在の依存lockfileと `urushi.lock` を残します。
2. パッケージ依存をnpm／pnpmで更新します。`urushi update`はパッケージマネージャーの依存更新を代行しません。
3. `urushi update --dry-run --json` でregistry差分を確認します。
4. `urushi update --json` を実行し、競合があれば解消します。競合時の終了コードは2です。
5. `urushi check --project tsconfig.json --strict --json` と、保存している `verify`／`workflow` シナリオを再実行します。配布CSSとテーマも確認します。

registry更新は、導入時の内容・ローカル編集・新しい内容の3者比較です。別の箇所への編集は維持できます。同じ行を双方が変更した場合は、自動で意味を判断して片方を捨てず、競合として返します。配布物からの新規導入・非競合更新・競合終了コードは `scripts/release-smoke.ts` で確認します。

## AI修正アダプター

`workflow --repair` は明示したソースをアダプターへ渡します。診断だけでなく、固定したシナリオの全手順も渡すため、最初の失敗より後の期待動作を確認できます。返答はパス・変更前ハッシュ・ファイル全文を持つJSONです。指定外パス、テスト、設定、古いハッシュは拒否します。

再検証に通らなければ、自動修正で書いた内容を元に戻します。途中でハッシュが変わったファイルは上書きせず報告します。同時編集をロックする機能ではないため、修正中は対象ファイルの並行編集を避けてください。

ビルドとアダプターは信頼したローカルコマンドとして設定します。CLIはそれらのプロセスを隔離しません。外部AIへ何を送るか、保存期間、回数や料金は利用者側のアダプターで制御します。GitHub CIのworkflow検査はローカルの決定的なアダプターを使い、AIへの送信を行いません。
