# 独自価値：なぜ shadcn や他のライブラリではなく、これを選ぶのか（2026-10-22）

## 結論

**見た目では差別化できない。** 見た目はすぐ真似される。

独自価値は「shadcn やほかのライブラリが、作りの都合上できないこと」に置く。今の設計にはそれが 4 つと補助が 1 つあり、うち 3 つは Phase 0 で実測・検証できた。

一言でいうと：**ブラウザが持っている UI をそのまま使う。だから軽く、壊れにくく、着せ替えられる。**

## 選ばれる理由

### 1. ほぼ JavaScript なしで動く

振る舞いはブラウザ標準（`<dialog>`、`popover`、anchor positioning、invoker commands）に任せている。

**実測（minify + gzip、React 本体は含まない、同じ条件で比較）**

| | Dialog と Popover |
|---|---|
| **yourlib**（Button を含む） | **0.99 KB** |
| Radix（shadcn の旧デフォルト） | 25.72 KB |
| Base UI（shadcn の現デフォルト） | 42.71 KB |

- 計測方法: `node scripts/size.ts <bench>`
- 補助スクリプト（Safari の `closedby` 用の代替処理）は任意で、0.43 KB。

**利用者にとってのメリット**

- 表示と操作が速い（INP に効く）。
- Server Components のまま使える。
- JS が読み込まれる前、または JS を切った状態でも、ダイアログやポップオーバーが開閉する（3 エンジンで検証済み）。
- Radix で起きている「閉じたあとに画面が操作できなくなる」類のバグが原理的に起きない。

**ほかがやれない理由**

- shadcn の全部品は Radix / Base UI の上に作られている。
- 土台をブラウザ標準に替えると、479 のレジストリを含むエコシステム全体が壊れるので、移れない。

### 2. 見た目を丸ごと着せ替えられる（実行時、範囲ごと）

- 部品のコードは意味だけを持ち、見た目はパック（DTCG トークン → CSS 変数）が当てる。
- `data-pack` 属性 1 つで、アプリ全体でも一部分だけでも切り替わる。

**利用者にとってのメリット**

- 顧客ごとにブランドを変える B2B SaaS（ホワイトラベル、マルチテナント）。
- 自社アプリの中に、別の見た目の埋め込みウィジェットを置ける。
- テーマ変更でコードを書き換えなくてよい。

**ほかがやれない理由**

- shadcn のスタイルは、インストール時にコピーしたコードへ Tailwind のクラスとして焼き付く。
- 実行時に顧客ごとに切り替えるには、コードを顧客の数だけ持つしかない。

### 3. AI に書かせても崩れない

- 見た目はパックの担当なので、呼び出す側の `className` で許されるのは配置（余白、幅、レイアウト）だけになる。
- 部品の契約から型・lint・ドキュメント・SKILL.md をすべて生成する。
- AI が色や角を直書きすると、lint がエラーにし、代わりに使うべきバリアントやトークンをエラー文で示す。

**利用者にとってのメリット**

- コーディングエージェントで画面を量産しても、デザインシステムが崩れない。

**ほかがやれない理由**

- shadcn は「Tailwind のクラスを自由に書き換えてよい」ことが価値の中心にある。
- そのため強く縛ることと両立しない。shadcn/lint はまだ v0.1。

### 4. コピーしても更新できる

- コピーされる部品のファイルは薄い（振る舞いはパッケージ、見た目はパックにある）。
- `yourlib.lock` に、インストールした版とハッシュを記録している。
- `yourlib diff` で、自分が変えたファイルが分かる（実装済み）。
- 3-way merge による `yourlib update` は Phase 2 で実装する。

**利用者にとってのメリット**

- 所有する自由と、修正を受け取れることが両立する。

**ほかがやれない理由**

- shadcn は「コードはあなたのもの」という思想から、`update` コマンドを持たない。

### 補助：日本語が最初から綺麗

- 約物の詰め（palt）
- 禁則処理（`line-break: strict`）
- 文節単位の改行（`word-break: auto-phrase`）
- 和文と欧文の間の空き（`text-autospace`）
- 日本語に合った行間

これらをパックの標準にしている。英語前提の shadcn には、この層がない。

## 正直な弱み（独自価値ではないもの・足りないもの）

- **見た目そのもの**: どの案も真似できる。差別化の柱にはしない。
- **部品の数**: 現時点で 3 つ。shadcn は 64。
- **AI の学習量**: AI がすでに覚えているのは shadcn。Skill・lint・llms.txt と、HTML に近い API で補う必要がある。
- **対応ブラウザ**: 新しいブラウザに限る（暫定で Chrome 135 / Safari 26.2 / Firefox 147 以上）。
- **閉じるアニメーション**: 今は Chromium だけ。Firefox と WebKit では即座に閉じる。
- **Safari のフォーカス**: マウスでクリックしてもボタンにフォーカスしない（Safari 本来の挙動）。そのため、マウスで開閉したときはトリガーにフォーカスが戻らない。キーボード操作なら戻る。
- **日本語組版の一部**（文節改行、約物の詰め）: 今は Chromium だけ。

## 価値を「見える化」する方法（デモとドキュメントのトップに置く）

1. **サイズ**: Radix / Base UI と並べた実測値。CI で毎回計測して表示する。
2. **JS を切るスイッチ**: 押しても、ダイアログとポップオーバーがそのまま動く。
3. **着せ替え**: 同じマークアップのままパックを切り替える。さらに一部分だけ別のパックにする。
4. **lint の体験**: AI が書いたコードを貼ると、エラーと直し方が出る。
5. **日本語組版の比較**: 一般的な既定値で組んだ場合と、このライブラリで組んだ場合を並べる。
